# Owner authority and asset recovery in 6.2

New NFT editions use one delegated execution mechanism: `grantAction` or an adopted `grantInstrument` creates the same account permission, and `executeInstrument` enforces it. Exact calldata commits the recipient and operation; a pinned target runtime, nonce, expiry, custody epoch, call count, per-call debit and remaining budget are checked. ERC20 approvals are limited to the allowed amount and cleared atomically after the call. The budget measures net debit of the selected asset, not every asset or liability in the account. Proxy implementation changes are not detected solely by a proxy runtime hash.

Legacy `createSession` and `executeSession` selectors explicitly revert in new editions. Revocation and storage compatibility remain. Existing immutable accounts are not upgraded by changing this source. The operator guard schedules a specific account permission and inherits its real remaining token or ETH budget. Sponsored requests use version-2 typed signatures including the exact account permission ID; owner and sponsor both consent, and the relayer's reimbursement cap applies even to an authorized failed inner operation.

The Authority & recovery panel lists current permissions, revokes them through owner review, checks selected-registry agent ownership and inspects the NFT's experiment cell. Agent identity verification means current ownership reported by that particular registry. It does not authenticate a trusted registry implementation, a service endpoint, reputation or work quality. A stale link can be removed by the current NFT authority and replaced with a newly verified link. Historical events remain public.

An unreadable tracked token no longer breaks the cell's commitment view. Snapshot hashes include its address, runtime hash, readable flag, state and evidence; an unreadable balance is never certified as zero. Owner-approved quarantine excludes it from unrelated adapter balance checks and forbids it as adapter input/output. Owner withdrawal back to the NFT remains available if the token permits transfer. Restoration requires a readable balance. Retirement frees a tracking slot only after a readable zero balance and keeps a historical commitment. External debt, untracked assets and outstanding approvals are not certified by these checks.

Validation includes real NFT mint/custody tests, exact token allowance/debit and replay tests, failed and malformed balance queries, quarantine/restoration/retirement, live agent-token ownership changes, and DOM tests for sponsorship edits and wallet changes during signature prompts. See `test/security/owner-safety.test.mjs`, `test/security/sponsor-review.test.mjs`, `test/extensions/agents.contracts.test.mjs` and `test/extensions/access.test.mjs`.
