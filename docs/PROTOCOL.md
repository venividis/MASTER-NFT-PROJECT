# Protocol specification

## Domain constants

All major commitments include explicit versioned domains. Implementations must not reuse a domain for a different encoding.

### Sovereign action statement

```solidity
keccak256(abi.encode(
  INTENT_TYPEHASH,
  account,
  chainId,
  target,
  value,
  dataHash,
  nonce,
  validAfter,
  validUntil,
  priorStateRoot,
  nextStateRoot,
  nextMemoryRoot,
  policyHash,
  evidenceHash,
  verifierId
))
```

The JavaScript planner and Rust proof kernel both mirror this exact encoding. The Rust suite includes a cross-language statement vector generated by ethers.

### Threshold attestation digest

```solidity
inner = keccak256(abi.encodePacked(
  "IDONTFUCKINGBELIEVEIT_ATTESTATION_V1",
  chainId,
  verifierAddress,
  statement
));
digest = EIP191(inner);
```

Signatures must recover to authorized signers in strictly increasing address order. Ordering makes duplicate signatures impossible without additional storage.

### Audit transition

For account execution:

```solidity
newAuditRoot = keccak256(abi.encode(
  oldAuditRoot,
  nonce,
  operatorOrRelayer,
  target,
  value,
  statement,
  keccak256(returnData),
  block.number,
  block.timestamp
));
```

The root is append-only under the assumptions of EVM transaction finality and collision resistance.

## State machine invariants

| ID | Invariant |
|---|---|
| I-01 | One token ID maps to one deterministic account address. |
| I-02 | The account's token tuple cannot change. |
| I-03 | Bound authority resolves from current ERC-721 ownership at call time. |
| I-04 | Session authority is target-, selector-, value-, time-, count-, and epoch-bounded. |
| I-05 | Ascension can occur at most once. |
| I-06 | Session epoch increases during Ascension, invalidating every prior session. |
| I-07 | Sovereign execution accepts exactly the next nonce. |
| I-08 | Sovereign proof statements are bound to chain and account. |
| I-09 | Sovereign transfer authorization is account-only. |
| I-10 | Sovereign mutable metadata authorization is account-only. |
| I-11 | Canonical genome evolution requires account state-root equality. |
| I-12 | A failed external call reverts root, nonce, and audit changes. |
| I-13 | Remote witness nonces strictly increase per identity/domain. |
| I-14 | Verifier runtime code hashes are checked on every proof. |
| I-15 | A frozen verifier/router/witness configuration has no unfreeze path. |

## ERC surfaces

The collection implements or exposes:

- ERC-165
- ERC-721 and metadata
- ERC-2981 royalties
- ERC-4907 users
- ERC-4906 metadata update events
- ERC-8048-style `metadata`, `getMetadata`, and `setMetadata`

The account implements:

- ERC-165
- ERC-1271 signature validation
- ERC-6551-inspired `token()`, `state()`, and `isValidSigner()` surfaces

The account is deployed by a purpose-built deterministic factory, not the canonical ERC-6551 registry. This is explicit to avoid a false interoperability claim.

## Reserved metadata

These keys are virtual and cannot be overwritten:

```text
core.seed
core.genome
core.stateRoot
core.memoryRoot
core.auditRoot
core.account
core.sovereign
agent-binding
```

They are derived from canonical contract/account state.

## Failure semantics

Proof router failures, verifier reverts, malformed proofs, target reverts, stale nonces, expired windows, wrong roots, wrong policy hashes, value limit violations, and cooldown violations all revert the action. There is no partial state transition.
