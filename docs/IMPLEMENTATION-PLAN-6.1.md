# ANIMA 6.1 — implementation plan revised against the actual NFT audit

Revision: 13 September 2026. This plan uses `ACTUAL-NFT-AUDIT.md` as its primary inventory, together with the later operational launchpad source. It preserves the original audit as a dated record.

## What changed

Shielded swaps, shielded hookless launches and encrypted group chat already exist. The immediate work is to expose, configure, connect and verify these implementations. It is not a new cryptography project. The hosted simulator's continuous optical scene is the camera reference to bring into the canonical runtime. Later public creator-hook launches, sales and auctions already work in local contract tests and must be retained.

## Authorized implementation sequence

1. **Canonical capabilities and actual routes.** Primary Swap, Launch, Commons and Vault must open the intended chain-capable interface. Local models remain explicitly selected tools. Keep the NFT owner and an ordinary wallet distinct, and expose verified configuration without automatic wallet connection.
2. **Private communication.** Integrate the existing encrypted groups into Commons: deployment or verified import of required contracts, room discovery, invitation consent, message history, key rotation, membership, backups and lock lifecycle. Basic chat requires only its actual dependencies. Exclude private text from visual effects and clear all secret fields on lock.
3. **One optical field and camera.** Port the documented continuous simulator scene into the canonical NFT renderer. Retain original optical identity, drag direction, pinch and wheel continuity, optional motion and panel transitions. Navigation never changes seed or reconstructs a substitute object.
4. **NFT launch custody.** Add an explicit verified NFT-account execution mode to supported launch, swap and liquidity operations. Use exact temporary approvals and current owner/epoch/nonce checks. Show signer, payer, beneficiary and transfer consequences before signature. Ordinary wallet mode remains available.
5. **Private creator-hook execution.** Connect the existing hooked factory to the RAILGUN composition path, checking hook identity and actual policy, exact funding, recoverable outputs and submission recovery. Never fall back to public execution. A RelayAdapt accounting test is not a ZK proof test.
6. **Participant access and economic continuity.** Add stable launch links and a participant view whose public terms can be read before wallet connection. Use actual sale/auction contracts for actions. Add conserved, reproducible scenario sequences with the selected hook fees, allocations, settlement and claims; optional vesting must create real vault rights.
7. **One release and recovery path.** Share canonical modules with the hosted entry, preserve the current Site audience, reconcile transaction replacement/cancellation/reorg states, update current capability documentation, rebuild exact archived runtime and verify source recovery. Save the complete project and publish the reviewed website update.
