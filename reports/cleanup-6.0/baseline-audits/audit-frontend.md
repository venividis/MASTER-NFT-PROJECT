# ANIMA frontend audit — read only

## Findings and decisions

1. **Keep the original blue object, actual volume interior, formation effect, and procedural sound; remove repeated UI/application layers around them.** The visual code is procedural, not a screenshot. The exterior shares optical equations between GLSL and Wasm (`web/renderer.js:1–35`, `render/field.inc`); Genesis adapts that renderer and adds a volumetric interior (`web/genesis/projection.mjs:6–44`, `web/genesis/interior-kernel.mjs:108–148`). Camera entry, free flight, pinch, double tap, pan, return and resume exist (`web/genesis/interior.mjs:34–65`, `web/genesis/interior-gestures.mjs:16–37`). Preserve this creative asset. Recommend simplifying its implementation and navigation, not replacing it with a new mascot or a generic dashboard.

2. **Fix the single source of truth before cosmetic cleanup.** The active Genesis build reads an already bundled `preview.html`, appends another shell and patches exact JS strings (`scripts/build-confluence.mjs:7–20`). `build-instruments.mjs` builds that preview from `web/reference/approved-1.2.html`, then concatenates numerous engine/controller modules with regex-stripped imports. `build-preview.mjs` and `build-kingdom.mjs` also write `preview.html` using different roots. Current authored `web/app.js` is not the source compiled into the main build; its archived copy is. Direct comparison found the archived model/renderer/audio/app identical to their current transformed source, but archived `fixed('address')` rejects the zero address whereas `web/evm.mjs` permits it. This is concrete drift, though not by itself an exploit. Keep baseline artifacts as immutable reference fixtures; build the active app from authored modules with a normal dependency graph. Move complete obsolete UIs into an explicit comparison archive; stop loading them into every primary session.

3. **Confirmed mixed provenance in connected visual evolution.** The live Confluence wallet and legacy wallet are separate. `web/confluence/app.js:111` connects `wallet`, then refreshes identity; it does not connect legacy `__idfbi.chain()`. `web/memory/renderer-bridge.js:20–21` suppresses local rehearsal life traits only when `original.chain()` is set or legacy historical state differs. Thus new-wallet connection does not block local life. `web/genesis/projection.mjs:54` swaps seed/genome/root at renderer parameter indices 0–11 and preserves `prior.slice(12)`, including local life at indices 23–30 (`renderer-bridge.js:7`). A minted seed can therefore be shown with local rehearsal activity deformation. Isolated Node VM execution of the actual renderer bridge confirmed Confluence-connected/legacy-disconnected retains nonzero local traits, while legacy-connected zeros them. This is a UI/provenance bug, not unauthorized chain execution. Use one selected identity and typed source (`local preview` or `confirmed chain`) for body, memory, activity, balance and receipts; any simulation overlay should be visibly opt-in.

4. **Refresh connected identity after receipts.** `web/confluence/wallet.mjs:24–34` captures the snapshot once on connect. `send():62–64` returns a transaction receipt without refreshing that snapshot. `web/confluence/app.js:83` stores receipt and pulses light but does not refresh connected seed/genome/root; its 500 ms loop (`:121`) refreshes only when the legacy/local root changes and the Confluence wallet is disconnected. Chain activity and ownership changes should be reflected from one confirmed snapshot/event reader, with stale/error state shown. Legacy `web/app.js:49` does refresh its own snapshot after sending, illustrating the inconsistent paths.

5. **Shorten repeated formation without deleting formation.** Genesis takes 12 seconds to open (`web/genesis/field.js:43,45`) and assigns visible control/text arrival across .37–.89 of that timeline (`creation.mjs:33–40`): roughly 4.4–10.7 seconds before most controls arrive; completion around 12 seconds. Controls are deliberately inert during that wait (`:36,39,44`). A “Complete formation” button and reduced-motion fallback exist (`:12,40,46`). Recommendation: keep an optional ceremonial first reveal; make repeat openings rapid, preserve focus/drafts, and let prepared controls work immediately or in a short stagger. Avoid losing the user's sense that the object creates the instrument.

6. **Merge navigation and operation names.** `web/confluence/app.js:19` declares many overlapping catalog entries; `atlasPage():60` adds the full original actions list and secondary views (`web/genesis/atlas.mjs:2–9`). Shell has header, orbit nodes, dock, separate Genesis entry strip and interior function navigation (`web/confluence/shell.html:3,5,8,14,19`). The `Original` action simply calls `open('home')` (`confluence/app.js:112`), while archived original v1.0 is a different route (`web/app.js:44,67`). Trade maps to v4, vault/journal/world map to live, exits maps to exit-live, while `rehearsal:` selects older instruments (`confluence/app.js:40–55`). One intentional primary navigation can retain every capability; keep legacy rehearsals and technical state inspection in clearly named secondary areas, not parallel everyday entry points. Use plain actions consistently (Swap, Launch, Vault, Memory, Commons, Worlds, Atlas).

7. **Unify the meaning of memory.** Original `SEAL MEMORY` hashes then discards both words and salt (`web/index.html:18`, `web/app.js:60`); encrypted notebook exists in local `MemoryEngine` (`web/memory/crypto.mjs:17–26`, `engine.mjs:8–10`); default Genesis Memory routes to live onchain inscription (`confluence/app.js:43`), which publishes plaintext after explicit consent (`live-protocol.mjs:91–96`). These are distinct products presented under similar names. Preserve all three if desired, but make one Memory surface with explicit storage/readability choice and retention explanation. Never imply the salted digest is a recoverable notebook. The notebook uses native AES-GCM and passphrase derivation; do not delete these protective controls.

8. **Correct “Export everything”.** Actual Confluence export contains only origin, instrument engine, routes, launch, Prism world, chain receipts (`web/confluence/app.js:92`); restoration writes those same known keys (`archive.mjs:12–14`). It is not a complete archive of every desk's configuration, privacy recovery material, external services, or deployed chain content. Replace label with an exact scope or implement a versioned manifest with explicit included/omitted components and separate sensitive recovery exports. Audit archive compatibility before deleting any old schema or localStorage key.

9. **Preserve real controls already implemented.** Confluence wallet owner checks, revision invalidation, epoch checks, exact reviewed transaction, fresh simulation before send and code-hash pinning for external extensions exist (`wallet.mjs:8–21,37–64`). Commons reads use block-pinned snapshots and re-check context (`live-protocol.mjs:98–166`); membership is posting control, not confidentiality (`:170–182`). Cartridge content is SHA-256 checked and run with sandbox + restrictive CSP (`wallet.mjs:36`, `confluence/app.js:76`). Do not remove these merely to shorten code or UI. Move technical details into expandable review sections where possible.

10. **Reduce performance plumbing and poll loops through shared lifecycle.** Base optical renderer schedules RAF continuously even paused (though actual GL rendering respects dirty/motion), and atmosphere is redrawn per frame (`renderer.js:80–85`). Genesis schedules separate RAF and controls projection (`field.js:56`); interior adds another RAF (`interior.mjs:56–67`); memory polls 400 ms (`renderer-bridge.js:27`) and Confluence polls 500 ms (`app.js:121`). This is complexity and battery-work risk, not a measured current-device FPS claim. One renderer/tick/state subscription, pause-on-hidden lifecycle, and event-driven identity updates should retain the optical result while reducing churn. The interior adaptive pixel/sample controller is a worthwhile asset (`interior-quality.mjs:1–97`); keep it. Software interior fallback is intentionally low-resolution (48/80 pixels along smaller viewport dimension with workers, 24 without, capped 144×120; `interior-cpu.mjs:25–36`), so do not promise identical fidelity on GPU-less devices.

11. **Consolidate audio rather than advertising unique tracks too strongly.** Original synth selects one of five pentatonic root pitches and three shared oscillator ratios (`web/model.mjs:156–166`, `audio.js:13–27`). Confluence independently instantiates four ambient oscillators with frequency derived from one identity coordinate (`confluence/app.js:58,114`), and an analyser drives light modulation (`:121`; `interior-kernel.mjs:102–104`). Actual identity variation and opt-in procedural audio exist; it is not yet a unique structured composition per NFT. One identity-derived sound engine with deeper rhythm/timbre development can meet that promise and avoid independent sound controls.

12. **Keep archived aesthetic variants, remove them from default payload/build authority after migration.** Begins and Spirit have separate geometry/surface/field/styles and are no longer the active Genesis renderer. Reuse shared geometric helpers, retain comparison outputs and reference tests, and eliminate duplicated runtime/UI code only after behavior parity is verified. `identityVector()` uses sixteen deterministic coordinates and Givens rotations (`web/confluence/identity.mjs:3–15`); this is a meaningful mathematical design mechanism, but rendered names have only 8×8 combinations and image uniqueness is not mathematically guaranteed. Existing UI acknowledges similar names/images (`confluence/app.js:67`).

## Further small cleanup candidates

13. **Collapse the CSS cascade once the active layout is fixed.** The fully reviewed Genesis stylesheet contains successive layouts overriding earlier layouts: header and content spacing, one-column instrument grid then two columns, later narrow/compact overrides, and several progressively stronger transparency rules (`web/genesis/styles.css:9–18,33–57,72–111`). Removing superseded rules after computed-style comparison will make the same design easier to change. Normalizing the variant body/surface class names shows every authored line in Begins and Spirit CSS is present in Genesis; the older styles are exact subsets after those identifier substitutions. Active Genesis controls mostly use 14–16 px type and 44–46 px minimum heights; do not generalize the legacy dashboard's many 5–9 px labels to the whole current interface. Preserve visible focus, reduced motion, keyboard-viewport compensation, accessible semantic controls and private-surface rasterization exclusions.

14. **Delete unreachable and inert implementation residue after reference checks.** `launchPage()` (`web/confluence/app.js:69`) is not selected by the page map, which routes launch into the v4 desk (`:67`); its old form/review branch can be retired together after checking archive compatibility. The active Genesis `qualityScale` updates (`web/genesis/field.js:57`) invoke `resizeOptics()` (`:26`), which only marks an optics flag; they no longer resize the removed optical framebuffer as Begins did. This tuning loop is ineffective residue, distinct from the working interior quality controller. `console-core.mjs` retains manifest/routing/split helpers that duplicate newer helpers; verify all consumers and migrate or remove rather than maintaining inconsistent schema/limit rules. `audioSource`, `audioElement`, and storage status variables are other candidates, not major product priorities.

15. **Generate feature status from a capability manifest.** The old local laboratory description (`web/operating/app.js:8`) calls House/Wager/Wake unimplemented, while later extension code implements a newer slice. Different eras' capability text should not all appear as current product truth. Keep local simulations, experimental code, testnet-connected mechanisms and deployment-verified mechanisms explicitly distinct, deriving status from one inventory. Do not treat archived test reports as current deployment evidence.

## Priority interpretation

The high-priority frontend problem is incoherent source/state authority, not insufficient visual ambition. Fix build inputs and selected-identity provenance first; refresh connected snapshots and label export/storage scope next. Then consolidate routes, memory/audio controls, CSS and dead branches. Preserve the blue object, reversible free-flight interior, formation, procedural sound, deterministic identity, receipts, simulations and explicit transaction reviews. A single coherent experience can retain broad capability without loading every historical interface as a parallel application.
