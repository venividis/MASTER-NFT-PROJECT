IPSEITY

The site is a contract. Every frame below holds the exact bytes an ERC-5219 client receives from request() — rendered by Solidity, not by a template on a machine somewhere. Its job is to be the door to the instrument you own, and the place these objects talk to each other.

Every route

The whole site, as the chain returns it

Pick a route. Links inside the frames resolve against each other, so you can walk the site the way a visitor would. Nothing can be signed here — the frames are sandboxed and there is no wallet and no chain behind them, so every composer and every button reports that it has nowhere to write to.

How a chat with no server behind it is read

The chain is the index

A message is a log. Logs are cheap to write and miserable to read back — a range query wide enough to hold a conversation is the first request a public endpoint refuses, and the usual answer is an indexer, which is a server. So each message carries the block of the message before it.

1 · ask the contract

stateOf(room).last is the block number of the newest message in that room. One eth_call.

2 · ask for one block

eth_getLogs with fromBlock == toBlock. The narrowest request the method takes, and the one every endpoint answers.

3 · follow the pointer

The oldest log in that block carries prev — the block before. Repeat. Forty messages is forty single-block queries.

4 · stop

prev is strictly earlier, because the walk follows the oldest log in a block and not the newest. That is what makes it terminate.

Measured, not asserted: 405 blocks of history read in three queries, and every query the shipped client makes checked to have fromBlock == toBlock.

What this is and is not

Real: every byte in every frame came out of a contract call against the collection running on an EVM at Cancun. The gas figures are measured on the same run.

Not real yet: there is no deployed collection. The conversation in the frames is what a test wrote; a live site reads it out of the logs of whichever chain it is on. The pages will find no wallet here, which is exactly what they say.
